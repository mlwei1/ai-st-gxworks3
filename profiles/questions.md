# 新用户「编程习惯」提问清单

AI 在首次为某位用户/某家公司生成工业程序前，先按需询问以下问题（不要一次问完，按任务挑 5~8 个）：

## 1. 标签与命名

1. 标签用**中文还是英文**？全局标签、局部变量、FB 形参是否统一？
2. 是否按类型加前缀？（例如 `b`=BOOL、`n`=INT、`t`=TIME、`x`=输入信号、`fb`=FB 实例）
3. 命名习惯：`bStart` / `b启动` / `启动按钮`，更习惯哪种？有没有固定的命名表？

## 2. 程序结构

4. 程序是否统一用「待机 / 自动 / 手动 / 停止中 / 报警 / 急停暂停」六模式？还是别的划分？
5. 主程序用**单 PROGRAM** 还是按设备拆 FB？气缸/电机类逻辑是否封装 FB？
6. 步进程序：步号从 0 还是 1 开始？步号是否存 D 寄存器供 HMI 显示？

## 3. 报警与异常

7. 气缸/电机动作超时默认多少秒？每台设备是否单独可配？
8. 报警时输出是保持还是全部关闭？步号冻结还是跳转？
9. 报警码怎么分配？（按气缸编号 / 按设备类型 / 是否有统一编码表）
10. 报警清除后允许哪些操作：继续/停止/从头？继续是从冻结步还是回待机？

## 4. 停止与急停

11. 停止是走停止序列（按顺序回原点）还是就地停？
12. 停止序列的顺序？夹爪/吸盘在什么时机释放？
13. 急停是“暂停等人处理”还是立即断电？急停后允许手动恢复吗？

## 5. 手动与 HMI

14. 手动按钮形式：点动（按住）/ 翻转（按一下到位、再按一下原位）/ 每个方向一个按钮？
15. 触摸屏地址规划：M 区按钮/状态/报警、D 区数据，是否已有固定地址表？
16. 是否需要导出 HMI 地址表（CSV/Excel）？

## 6. 注释与交付

17. 注释用中文还是英文？每步/每个 FB 是否要写用途说明？
18. 交付物除了 `.st` + XML，是否还需要 IO 表、HMI 地址表、报警表、操作说明？

> 用户回答后，把稳定偏好写入 `profiles/<scope>/<name>.json`；一次性需求留在 spec，不进档案。
