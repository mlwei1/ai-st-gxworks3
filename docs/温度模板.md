# 温度模板（temperature_two_position）

> 第二个工业场景模板：**位式（ON/OFF）温度控制**，带回差与传感器超量程保护。
> 全部用 ST 通用逻辑实现，不依赖定位/模块 FB，因此**可直接在 Simulator3 中验证**（写 D100、读 Y0/Y1）。

## 1. 用法

```bash
node --experimental-strip-types --no-warnings src/cli.ts gen specs/temperature_two_position.json -o out/temperature
```

示例 spec：[specs/temperature_two_position.json](../specs/temperature_two_position.json)

```json
"template": {
  "name": "temperature_two_position",
  "params": { "setpoint": 600, "hysteresis": 20, "tempMin": -500, "tempMax": 1500 }
}
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `setpoint` | 设定温度（0.1°C，600 = 60.0°C） | 600 |
| `hysteresis` | 回差（0.1°C，20 = 2.0°C） | 20 |
| `tempMin` / `tempMax` | 传感器量程（0.1°C），超量程置故障 | -500 / 1500 |

IO 约定：`X0` 启动、`X1` 停止；`Y0` 加热、`Y1` 冷却；`D100` 当前温度（INT，0.1°C）。
温度可由模拟量模块（如 FX5-4AD）或通信写入 D100（本模板不包含 AD 转换）。

## 2. 控制逻辑

```st
nTemp := D100;                                  // 当前温度（0.1°C）
IF nTemp <= nTempMin OR nTemp >= nTempMax THEN bErr := TRUE; END_IF;  // 超量程故障

IF X1 THEN bRun := FALSE; END_IF;
IF X0 AND NOT bStartLast AND NOT bErr THEN bRun := TRUE; END_IF;
bStartLast := X0;

IF bRun AND NOT bErr THEN
    // 加热：≤ 设定-回差 开；≥ 设定 关
    IF nTemp <= nSet - nHyst THEN bHeat := TRUE; END_IF;
    IF nTemp >= nSet THEN bHeat := FALSE; END_IF;
    // 冷却：≥ 设定+回差 开；≤ 设定 关
    IF nTemp >= nSet + nHyst THEN bCool := TRUE; END_IF;
    IF nTemp <= nSet THEN bCool := FALSE; END_IF;
ELSE
    bHeat := FALSE; bCool := FALSE;
END_IF;

Y0 := bRun AND bHeat;
Y1 := bRun AND bCool;
```

以默认参数（设定 60.0°C、回差 2.0°C）为例：

| 当前温度 | 加热 Y0 | 冷却 Y1 |
|---|---|---|
| ≤ 58.0°C（580） | ON | OFF |
| 58.0°C ~ 60.0°C | 保持（回差） | OFF |
| 60.0°C ~ 62.0°C | OFF | 保持 |
| ≥ 62.0°C（620） | OFF | ON |
| 超量程（<-50.0 或 ≥150.0°C） | OFF | OFF（bErr，回到量程内可重新启动） |

## 4. 仿真计划（下一步）

场景文件：`sim/temperature_two_position.sim.json`（已写好，待 GX Simulator3 执行记录 `.obs.json`）：

1. 启动 X0=1，D100=0（冷态）→ 期望 `Y0=1`（加热）；
2. D100=600（到设定）→ 期望 `Y0=0`；
3. D100=620（设定+回差）→ 期望 `Y1=1`（冷却）；
4. D100=600 → 期望 `Y1=0`；
5. D100=2000（超量程）→ 期望 `Y0=0, Y1=0` 且故障可复位（X1 后重新 X0）。

在 GX Simulator3 中写 D100、读 Y0/Y1，记录 `.obs.json` 后用 `sim` 命令断言。


## 6. GX Simulator3 仿真自动化限制（2026-11-11 实测）

本机通过 MCP/UI 自动化操作 GX Works3 时：

- ✅ 能启动仿真、自动写入程序、打开批量监视、读取 Y/D 等设备值；
- ❌ **批量监视写入当前值**在自动点击路径下不可靠（双击单元格后键入不生效）；
- ✅ 「调试 → 强制输入输出登录/解除」可强制 **X/Y 位软元件**（已实测 X0 可强制 ON/OFF）；
- ❌ 该功能明确只接受 X/Y（提示“请输入XY软元件”），**无法强制 D100 等数据寄存器**；
- ❌ 「调试 → 当前值更改」在自动路径下未弹出可用对话框。

结论：温度模板的完整仿真（需要写 D100 多个温度值）**必须人工在 GX 中操作**，
或后续改用“自驱动测试 harness 程序”（程序内部按时间改 D100，只读取结果）的方案。
本轮未获得 `.obs.json`，因此不声称仿真 PASS。

## 8. 自驱动仿真 harness（2026-11-11）

为绕开“无法自动写 D100”的限制，新增测试脚手架：
[sim/temperature_two_position.harness.st](../sim/temperature_two_position.harness.st)。

- 用 SM412（1 秒时钟）推进 7 个阶段；
- 程序内部依次把 D100 设为 0 / 600 / 620 / 600 / 2000 / 0；
- 每阶段结束把 Y0/Y1 记录到 D310~D316；
- 第 7 阶段自检，结果写 D320（0=PASS，1=FAIL）。

已构建 XML（`out/temp_harness/temperature_two_position.harness.xml`，XSD PASS），
并在 GX Simulator3 中尝试执行；但本轮 GX 页面未确认程序写入/运行状态（D100 恒为 0），
因此**不声称 harness 执行 PASS**。下一轮先显式执行“在线 → 写入至可编程控制器”，再启动监视验证。

### 8.1 显式 PLC 写入路径（2026-11-11 实测）

GX 模拟开始后若未执行程序，需手动走一遍完整写入：

1. 在线(O) → 写入至可编程控制器(W)... → 「在线数据操作」；
2. 选「参数+程序(F)」→ 点「执行(E)」；
3. 弹窗「远程STOP后，是否执行可编程控制器的写入？」→ **是(Y)**；
4. 弹窗「以下文件已存在，是否覆盖？」→ **全部是(A)**；
5. 写入完成后弹窗「CPU处于STOP状态。是否执行远程RUN？」→ **是(Y)**；
6. 显示「已完成。」→ 确定，关闭「在线数据操作」。

本轮按上述路径执行后，仿真窗口显示 RUN / P.RUN 绿灯，但批量监视里 D100、D310~D316、D320 仍全为 0，
说明**程序仍未真正执行**（或批量监视未连接到新写入的程序）。下一步需要：
- 打开程序本体确认导入的 ST 代码在 GX 中非空；
- 检查「程序 → 扫描」任务的执行类型/程序登录状态；
- 或改用 GX 的「从可编程控制器读取」回读程序，确认写入内容。

### 8.2 程序执行诊断探针（2026-11-11 已实测）

用 `sim/probe_scan.st`（诊断用，不属于模板）在 Simulator3 中验证：

- D0 = 扫描计数 → **18197 且持续递增**（程序确实在执行）；
- D1 = TON 1s 计数 → **88**（定时器正常推进）；
- D2 = SM412 计数 → 循环变化（1 秒时钟正常）。

结论：
1. 「模拟开始」自动写入 + 打开监视后，**ST 程序、TON、SM412 在 Simulator3 中均正常执行**；
2. 之前 harness 读到全 0，最可能是**监视窗口在 PLC 写入前打开，写入/远程 RUN 后监视数据未刷新**；
3. 正确顺序：启动仿真（自动写入）→ 等写入完成 → 再打开批量监视 → 读 D 寄存器。

证据：`docs/evidence/M3/11-sim-program-exec-probe.png`。
