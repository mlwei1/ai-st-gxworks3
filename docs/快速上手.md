# 快速上手（v0.2）：Spec/ST → IEC XML → 纯 ST 模板工程

> 5 步，全部在本机验证过。GX Works3 用 1.128，CPU 用 FX5U。

## 先理解（v0.2 的正确认知）

早期 v0.1 文档说「IEC61131-10 XML 导入后程序内容为空」——**这是错的**（当时用错了 XML schema）。
实测结论：

| 元素 | 能否随 XML 一次导入 |
|---|---|
| Program / FunctionBlock / Function 正文 | ✅ |
| 局部标签、全局标签、结构体 | ✅ |
| CPU 模块 / 任务配置 | ❌（由**模板工程**提供） |

所以正确流程是：**复制纯 ST 模板工程 → 导入 XML → 全部转换**，
不需要再手工粘贴 ST 或导入标签 CSV。

## 第 0 步：准备

- Node.js **22.6+**（原生 TypeScript 类型剥离，无需编译）
- GX Works3 **1.128**（FX5U）
- 模板工程：`templates/FX5U_ST_Template.gx3`（FX5U + ST，无梯形图）

## 第 1 步：生成工程包

偏好 Spec 驱动（推荐）：

```bash
cd 'C:\Users\52900\Documents\项目\ai_st_gxworks3'
node --experimental-strip-types --no-warnings src/cli.ts gen specs\motor_start_stop.json -o out\run1
node --experimental-strip-types --no-warnings src/cli.ts gen --list-templates   # 查看 10 个模板
```

或者从已有 `.st` 直接转换：

```bash
node --experimental-strip-types --no-warnings src/cli.ts check 你的程序.st
node --experimental-strip-types --no-warnings src/cli.ts build-xml 你的程序.st -o out\run1
```

产物：

```
out/run1/
├── motor_start_stop.st      ← ST 源码（人工核对/备份）
├── motor_start_stop.xml     ← ★ 导入 GX Works3 用
├── Main_local_labels.csv    ← 标签备份（可选）
├── manifest.json            ← spec/模板/诊断/生成器信息
└── diagnostics.json
```

## 第 2 步：复制模板（不要直接改模板）

```powershell
copy templates\FX5U_ST_Template.gx3 %TEMP%\run1.gx3
```

## 第 3 步：导入

1. GX Works3 打开 `%TEMP%\run1.gx3`
2. 菜单：**工程 → 导入 → IEC61131-10 XML格式**
3. 选择第 1 步生成的 `.xml` → 打开 → 确认导入
4. 菜单：**转换 → 全部转换（Shift+Alt+F4）** → 点 OK

预期：**Error 0 / Warning 0**（截图为证见 `docs/evidence/`）。

## 第 4 步：常见报错

| 报错 | 原因 | 处理 |
|---|---|---|
| `0x11021040` | 全局变量落在锁存区（FX5U 默认 D200 及以上）但没有 RETAIN | 在 ST 里给该变量加 `RETAIN`（工具已自动按 retain 分组导出） |
| 导入后没有程序 | 目标工程里同名 Program 的执行类型不一致 | 用模板工程，不要用业务工程当模板 |
| `X198` 等设备地址报错 | X/Y 是八进制 | 改成 `X1777` 范围内的合法八进制 |
| 编译通过但设备不动作 | 程序未下载/未启动 | 这是下载与运行环节，不是生成环节 |

## 仿真调试（不接 PLC 验证程序行为）

1. 工程全部转换通过后：**调试 → 仿真 → 开始仿真**（Debug → Simulation → Start Simulation）；
2. 状态栏出现 `Simulation (1)`，标题变为 `Monitoring (Read Only)` 即已在线仿真；
3. **在线 → 监视 → 设备/缓冲存储器批量监视**，输入 `X0` 回车 → `Start Monitoring`；
4. 双击位单元格输入 `1`/`0` 写入输入点，再监视输出点（如 `Y0`）确认程序动作；
5. 结束：**调试 → 仿真 → 停止仿真**。

> 注意：生成的程序文件必须落在 **Scan（循环执行）**；工具已按官方样例输出
> `<ResourceExecutionType type="scan"/>`，若手工改过 XML 需保持该设置。

### 用场景文件做仿真断言

```bash
# 1) 查看场景清单 / 生成观测模板
ai-st-gxworks3 sim sim\motor_start_stop.sim.json --write-obs-template obs.json

# 2) 在 GX Works3 仿真中按清单写输入、读输出，把读到的值填进 obs.json
# 3) 断言（生成 out/<scenario>-sim/report.json）
ai-st-gxworks3 sim sim\motor_start_stop.sim.json --observed obs.json
```

已跑通示例：`sim/motor_start_stop.sim.json`（启停）、`sim/tank_level.sim.json`（液位）、
`sim/alarm_first_out.sim.json`（报警首出）均为 4 步全部 PASS（证据 `docs/evidence/M2/`）。复核方法见
[M2 验收复核指南](M2-验收复核指南.md)。操作要点：
批监视列是位 `7..0`（八进制设备 `X1` 在 `X0` 行的“1”列）；写后切到输出设备重新监视读取。

当前为**半自动**执行（GX Simulator3 没有公开的读写 API）；后续接 OpenIF/UI 自动化后可全自动。

## ST 步进程序（SFC/STL 风格，M3+）

工位分步动作不再需要梯形图 SFC/STL：在 spec 里写 `sequence` 段，`gen` 生成等价 ST。

```bash
node --experimental-strip-types --no-warnings src/cli.ts gen specs\robot_transfer_steps.json -o out\robot_steps
```

`sequence.steps[]` 每步包含：`actions`（ON/OFF 或表达式）、`next`（转移条件/延时/目标步，可多分支）、
`initialStep`、`startCondition/stopCondition/faultCondition`。生成代码是 `nStep` 步号状态机 + `CASE`，
逐行可审查，详见 [ST步进程序.md](ST步进程序.md)。
## 交付工程包（M3）

```bash
node --experimental-strip-types --no-warnings src/cli.ts deliver specs\motor_start_stop.json -o out\deliver_motor
```

产出 `report.md`（含需求追溯矩阵）、`trace.json`、`delivery.json`（SHA256）、`artifacts/`（ST/XML/CSV）。
如需把仿真/GX 证据一起归档：`--sim <report.json> --native-evidence 截图.png`。
详见 [M3-交付与MCP.md](M3-交付与MCP.md)。

## MCP Server（M3，供 AI Agent 调用）

```bash
node --experimental-strip-types --no-warnings src/cli.ts mcp
```

stdio JSON-RPC 服务，提供 `st_check` / `spec_generate` / `st_build_xml` / `sim_validate` / `deliver`
五个工具；在 Claude/DeepSeek 的 MCP 配置里把 command 指向上面这条命令即可。零运行时依赖。
## 可选：LLM 兜底 / 编译诊断回灌

```bash
# 模板覆盖不了的非标逻辑（需要 ANTHROPIC_BASE_URL + ANTHROPIC_AUTH_TOKEN）
gen specs\xxx.json --llm -o out\llm1

# 把 GX Works3 全部转换的错误整理成 JSON/文本，带着真实错误重新生成
gen specs\xxx.json --llm --compiler-errors errors.json -o out\fix1
```

详见 [编译诊断回灌.md](编译诊断回灌.md)。
