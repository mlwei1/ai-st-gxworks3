# 快速上手：把 AI 生成的 ST 装进 GX Works3

> 5 步。每一步都有明确的菜单路径，照做即可。

---

## 先理解 GX Works3 的硬约束

这决定了为什么不能用「AI 直接生成工程文件」：

| 元素 | 位置 | 外部能否写入 |
|---|---|---|
| 全局标签 | 全局标签工作表 | ✅ **CSV 导入**（XML 只能导出） |
| 局部标签 | 「标签设置」工作表 | ✅ **CSV 导入**（XML 只能导出） |
| ST 程序本体 | 「程序本体」工作表 | ✅ 粘贴（ST 编辑器是纯文本） |
| 梯形图 | 梯形图编辑器 | ❌ 剪贴板是专有二进制 |
| 整个工程 | `工程 → 导入 → IEC61131-10 XML格式` | ❌ 导入后程序内容为空 |

所以工作流是**三块并行落地**：

```
全局标签  →  CSV 导入（自动）
局部标签  →  CSV 导入（自动）
程序本体  →  复制粘贴
```

---

## 第 0 步：先在 GX Works3 里建好工程

**这一步不能跳过** —— 没有 CPU 模块配置，程序挂不上去（表现为"导入成功但看不到内容"）。

1. 打开 GX Works3 → `文件 → 新建` → **工程**
2. 系列选 **FX5U**，机型按实际 CPU 选
3. 程序语言选 **ST**
4. 勾选 **「使用标签」**
5. 工程向导里把模块配置填好（至少 CPU + 实际用的 IO 模块）
6. 完成 → 保存工程

> GX Works3 只有「结构化工程」模式，没有「简单工程」选项。

## 第 1 步：生成文件

```bash
cd 'C:\Users\52900\Documents\项目\ai_st_gxworks3'

node --experimental-strip-types --no-warnings src/cli.ts build-text 你的程序.st -o ./out
```

产出：

```
out/
├── Main.st                 ← 程序本体（粘贴用）
├── Main_labels.txt         ← 标签录入表（备选）
├── Main_local_labels.csv   ← 局部标签 CSV ✅ 推荐
├── FB_Motor.st
├── FB_Motor_labels.txt
├── FB_Motor_local_labels.csv
├── Global.csv              ← 全局标签 CSV ✅ 推荐
└── local_labels_table.txt  ← 全部局部标签汇总
```

想直接让 AI 写代码：

```bash
node --experimental-strip-types --no-warnings src/cli.ts generate "水箱液位控制，低于10%启动水泵，高于90%停泵" --io examples/io_table.txt --out ./out
```

---

## 第 2 步：导入局部标签

对**每个** Program 和 FB 都要做一次：

1. 导航窗口 → 找到目标 `Program` 或 `FB/FUN` 节点
2. **右键** → `局部标签`
3. 选 **导入文件(&I)...**
4. 选对应的 `*_local_labels.csv`（如 `FB_Motor_local_labels.csv`）
5. 提示覆盖/新增时选确定

> 文件名的 POU 名要和工程里的节点名**完全一致**。
> `FB_Motor_local_labels.csv` 只能导给名为 `FB_Motor` 的 FB。

---

## 第 3 步：导入全局标签

1. 导航窗口 → **全局标签**
2. **右键** → `导入文件(&I)...`
3. 选 `Global.csv`
4. 确定

如果提示同名标签冲突，选**覆盖**或先删掉工程里已有的同名标签。

---

## 第 4 步：粘贴程序本体

对每个 POU：

1. 双击打开该 POU → 切到 **「程序本体」** 工作表
2. 用记事本 / VS Code 打开对应的 `.st` 文件（例：`out/FB_Motor.st`）
3. **Ctrl+A** 全选 → **Ctrl+C**
4. 回到 GX Works3「程序本体」→ **Ctrl+A** → **Ctrl+V**

> `.st` 文件顶部有一段 `(* 本 POU 需在「标签设置」工作表建立的局部标签 *)` 注释，
> 它只是给你核对用的，粘进去不影响编译。想去掉就加 `--no-declare`。

---

## 第 5 步：编译验证

菜单 `转换 → 全部转换`。

| 报错 | 原因 | 解决 |
|---|---|---|
| 变量未定义 | 局部标签没导进去 | 回第 2 步，确认每个 POU 都导了 |
| 类型不匹配 | 标签类型建错 | 检查 CSV 第 3 列「数据类型」 |
| 语法错误 | 粘贴不完整 | 重新 Ctrl+A → Ctrl+V |
| 找不到 FB 实例 | FB 的局部标签没导 | 回第 2 步导 FB 的 CSV |

## 标签 CSV 的格式说明

工具生成的文件与 GX Works3 导出的**逐行逐列一致**，关键点：

| 项 | 要求 |
|---|---|
| 分隔符 | **TAB**，不是逗号 |
| 引号 | 每个字段都带双引号 |
| 第 1 行 | **工程名**（未设置工程时为 `(工程未设置)`） |
| 第 2 行 | 表头 |
| 局部标签 | **27** 列 |
| 全局标签 | **28** 列（多「外部设备的访问」列，值 `0`） |
| 编码 | **UTF-16LE + BOM** |
| 换行 | LF |

> ⚠️ 自定义类型名（如 `ST_Motor`）**必须保持原样大小写** ——
> GX Works3 区分大小写，写成 `ST_MOTOR` 会指向一个不存在的类型。

## 完整示例（motor_demo）

```bash
node --experimental-strip-types --no-warnings src/cli.ts build-text examples/motor_demo.st -o examples/out_motor
```

工程里需要建两个 POU：

| 工程节点 | 导入的标签 CSV | 粘贴的 ST |
|---|---|---|
| `Main`（Program） | `Main_local_labels.csv` | `Main.st` |
| `FB_Motor`（FB） | `FB_Motor_local_labels.csv` | `FB_Motor.st` |

外加 `Global.csv` 导进全局标签。

## 备选方案：手工录入

如果局部标签的 CSV 导入在你的版本上有问题：

- **全局标签** → 右键 → 导入 → `global_labels.csv`（本工具生成的是 UTF-16 的 `Global.csv`，
  若失败可改用 CSV 版）
- **局部标签** → 打开 POU 的**「标签设置」**工作表，照着 `*_labels.txt` 逐行录入：

  ```
  方向    标签名              数据类型   初始值   软元件     注释
  输入    bEnable             BOOL                         启动命令
  输出    bRunning            BOOL                         运行状态
  局部    tRampTimer          TON                          斜坡定时器
  局部    nRampStep           INT          0              斜坡步进
  ```

- **程序本体**照样粘贴 `.st`

## 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 导入报「文件格式不正确」 | CSV 是 UTF-16 存的，某些旧版本只认 ANSI | 用 Excel 另存为「Unicode (UTF-16 LE)」或用本工具重新生成 |
| 导入成功但看不到内容 | 工程没配 CPU 模块 | 补做工程向导的模块配置 |
| 标签导不进去 | POU 名与文件名不一致 | 改文件名或改 POU 名使其一致 |
| 局部标签报重复 | 工程里已有同名标签 | 先删除旧的，或导入时选覆盖 |
| 局部标签软元件冲突 | 显式地址占了自动分配区 | 局部标签的软元件**留空**，让编译器自动分配 |
| 自定义类型找不到 | 类型名被改成了大写 | CSV 里保持 `ST_Motor` 原样 |
