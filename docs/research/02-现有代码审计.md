### 1.2 逐模块一句话结论

- **dialect（解析+检查）**：骨架可用，但知识库与恢复机制必须重写。解析器当前接受/拒绝的语法集合没有经过任何 GX Works3 原生编译验证，而 analyzer 的 E 类诊断口径来自错误的事实表 —— 「本地检查通过 ≠ 可编译」的主要来源。
- **emit（文本+CSV）**：CSV 是 v0.1 最有价值的资产（与真实导出样本字节一致）；文本输出方向正确（正文只含语句），但顶部块注释、`//!DECLARE`、REPEAT 反解析存在编译风险。
- **ai（提示词+转换）**：client 可保留；prompt 的「三菱事实」必须整体重写；convert 需要版本化 schema + 直接生成 AST（不要二次解析丢注释）。
- **cli**：三个子命令的骨架可复用，但缺少 native 编译、仿真、交付阶段；`build-xml` 已从代码移除而文档/package.json 仍引用。

## 3. 事实核对（重点）

> 依据：本机 e-Manual 原文（手册号 + 手册内页 `text/xxxxx.html`）。本机可用的 FX5/iQ-R 手册：JY997D58701（FX5 用户手册·应用篇）、JY997D58901（FX5 编程手册·指令/通用FUN/FB篇）、JY997D63101（FX5 CPU 模块 FB 参考）、SH081316（iQ-R CPU 模块用户手册·应用篇）、SH081322（iQ-R 编程手册·CPU模块用指令/通用FUN/通用FB篇）、SH081271（GX Works3 操作手册）。网页与 PDF 仅作辅助（web_fetch 不支持 PDF，故正文以本机 e-Manual 为准）。

### 3.1 FX5U 软元件范围（代码 `instructions.ts:224-237`、`prompt.ts:76`）

**手册值【已验证】**（JY997D58701 · `text/08003.html`「软元件点数的使用范围」及 `text/06000.html`「软元件一览」；Lead 已复核）：

| 软元件 | 代码现值（FX3U 口径） | FX5S/FX5U/FX5UC 手册值 | 判定 |
|---|---|---|---|
| X（输入，**八进制**） | 0–511 | X0～X1777（八进制，十进制 0–1023） | **错**（上限 + 进制） |
| Y（输出，**八进制**） | 0–511 | Y0～Y1777（八进制） | **错** |
| M 内部继电器 | 0–767 | M0～M32767 | **错** |
| L 锁存继电器 | 0–767 | L0～L32767 | **错** |
| B 链接继电器（**十六进制**） | 0–63 | B0～B7FFF | **错** |
| S 步进继电器 | 0–127 | S0～S4095 | **错** |
| T 定时器 | 0–511 | T0～T1023（ST0～ST1023 同） | **错** |
| C 计数器 | 0–255 | C0～C1023（LC0～LC1023 同） | **错** |
| D 数据寄存器 | 0–7999 | D0～D7999 | 对 |
| W 链接寄存器（**十六进制**） | 0–511 | W0～W7FFF | **错** |
| R 文件寄存器 | 0–32767 | R0～R32767 | 对 |
| Z 变址寄存器 | 0–19 | 可配置 0～24（默认 20，2 点为单位），与 LZ 合计 24 字 | 部分对（缺 LZ/可配置） |
| ST/LC/SM/SD/ER | 缺 | ST0～ST1023、LC0～LC1023、ER0～ER32767、SM/SD 系统软元件 | 缺 |

**FX5UJ 是更小的变体（同页手册）**：M0～M7679、B0～B7FF、F0～F127、T0～T511、ST0～ST15、C0～C255、LC0～LC63、L0～L7679、W0～W3FF、SW0～SW3FF。**代码与提示词完全不区分 FX5UJ/FX5S/FX5UC** → 按 FX5U 上限放行会漏报，按 FX3U 上限收紧会误报。

**结论**：`DEVICE_RANGES` 与提示词中的「FX5U 设备范围」整体是 **FX3U 口径，属重大事实错误**；只有 D/R 两项正确。

### 3.2 X/Y 八进制解析缺失【已验证 → 高影响】

- 手册明确 X/Y 进制为 **8 进制**（JY997D58701 `text/06000.html`；指令手册 `text/04000.html` 也写「输入输出编号 0～1777(8进制)」）。
- 代码 `instructions.ts:276-281 parseDeviceAddress()` 用 `[0-9]+` 十进制解析；`analyzer.ts:286-294`、`438-446` 直接拿十进制数值与 511 比较。
- 后果：`X1777`（合法）→ 数值 1777 > 511 → 误报 E009/E006；`X1000`（合法，八进制=512）→ 误报；`M1000`（合法）→ 误报。反向：`X198` 数值 198 ≤ 511 会**放行**，但 8/9 不是八进制数字 → GX Works3 输入/编译时报错。**既误报又漏报**。
- iQ-R 的 X/Y 同样是**十六进制**（SH081316 `text/0D000.html`：R00/R01/R02 为 X0～X1FFF(8192点)、其他为 X0～X2FFF(12288点)），代码同样没有进制概念。

### 3.3 iQ-R 范围（`prompt.ts:79`）【已验证 → 错】

提示词写 `X0-X2047, Y0-Y2047, M0-M32767, D0-D32767`。手册（SH081316 `text/1A001.html`、`text/0D000.html`）实际：X/Y 到 **X2FFF/Y2FFF**（小机型 X1FFF），M/D 为可配置的大范围（手册表中 M 最大到千万级、D 到千万级，具体默认点数需查 iQ-R CPU 手册的默认设置表 → **默认值待验证**）。至少 X/Y 数值与进制都写错。且 **`analyzer.ts` 的 `target` 选项只存不用**（`analyzer.ts:61,104` 存了 target，但设备范围与 FB/指令表全部固定为 FX5U），`--target iQ-R` 实际仍按 FX5U 检查。

### 3.4 类型系统

**FX5 支持的类型【已验证】**（JY997D58901 `text/03001.html`「作为标签处理的数据」）：位(BOOL)、字[无符号]/位串[16位](WORD)、双字[无符号](DWORD)、字[带符号](INT)、双字[带符号](DINT)、单精度实数(REAL)、时间(TIME)、字符串(STRING)、字符串[Unicode](WSTRING)、定时器(TIMER)、累计定时器(RETENTIVETIMER)、计数器(COUNTER)、超长计数器(LCOUNTER)、指针(POINTER)。

- 代码 `types.ts:11-27`、`prompt.ts:10` 额外列出 **LINT、ULINT、LREAL**：本机 **FX5 手册全文未出现**（LREAL 只在 iQ-R 手册出现，如 SH081316 `text/1B003.html`）→ **FX5 不支持，代码假设/错**。analyzer 对 DIAG 未知类型放行（`analyzer.ts:256-259`）→ AI 可声明 LREAL 通过本地检查，GX Works3 编译失败。
- 代码缺 **TIMER / RETENTIVETIMER / COUNTER / LCOUNTER / POINTER** → 正确的三菱写法被 analyzer 判 E004 未知类型。
- `types.ts:35-51` 的 `TYPE_WORD_WIDTH` 把 STRING/WSTRING 记 1 字（手册：字符串存储按字节数换算字数，`text/03001.html`）→ 类型宽度/占用推断不可靠。

**字符串引号规则【已验证 → 代码正确】**（JY997D58901 `text/03001.html`）：ST 程序中 `STRING` 用**单引号**、`STRING[Unicode]`(WSTRING) 用**双引号**（梯形图/FBD 才允许单/双引号混用）。`lexer.ts:143-196` 的 `'...'=STRING`、`"..."=WSTRING` 与手册一致。但 **`prompt.ts` 没有把这条规则告诉模型**（只写了“注释用 //”），AI 很可能用双引号写 STRING → 类型不匹配/编译失败。

**SQRT【已验证】**（JY997D58901 `text/0C073.html`）：`SQRT` 指令**不支持 ST 语言/FBD**，ST 中应使用**通用功能 `SQRT(_E)`**。代码把 SQRT 列在 `STANDARD_FUNCTIONS` 函数白名单并用 `SQRT(x)` 表达式形式 → **与手册一致，正确**。风险只在「AI 误写成 EN/ENO 指令形式或不存在的 `SQRT_E`」。

### 3.7 其他语法事实

| 事项 | 结论 | 依据 |
|---|---|---|
| ST 中可否直接写软元件 | **可以**（手册 ST 示例 `Y1:=(X0 OR X1) AND X2 AND NOT X3;`） | JY997D58901 `text/0A000.html`【已验证】→ `examples/motor_demo.st` 的 `Y0 := FALSE;` 写法合法 |
| 字符串常数引号 | 单引号=STRING，双引号=WSTRING | JY997D58901 `text/03001.html`【已验证】 |
| 注释 | ST 编辑器有“注释”着色；**块注释 `(* *)` 是否被 ST 编译器接受未在手册中找到明文** | 【待验证】；而 `renderPOUAsText` 顶部生成的正是 `(* ... *)` 多行块注释 → 若 GX 不接受即为编译失败 |
| REPEAT 语法 | 本机手册的 ST 语法规格在《程序设计篇》（JY997D58801，未安装）。当前 `parser.ts:927-934` 接受 `REPEAT … UNTIL cond;`（无 `END_REPEAT`），`unparser.ts:146-151` 也不输出 `END_REPEAT`；IEC 标准要求 `END_REPEAT;` | 【待验证·高风险】；同时该语法会让 `parseProgram` 在遇到 `END_REPEAT` 时可能陷入死循环（`END_REPEAT` 被 `parseStatements` 直接 break 而无人消费） |
| 变量注释（`//`） | 词法器把 `//` 当空白丢弃；parser 只把 `;` 之后的 **string token** 当注释（`parser.ts:546-556`）→ `//` 注释永远进不了 AST | 【已验证·功能缺陷】实测 `motor_demo.st` 12 条变量注释捕获 0 条，标签 CSV 注释列全空 |
| 标签未分配软元件时的行为 | 转换时标签按填充块分配到**标签存储器/锁存标签区域**，不是“自动分配软元件地址” | SH081271 `text/0A023.html`【已验证】→ `AUTO_ALLOCATE_GUARD`（M8000/D512）无手册依据 |
| 分配软元件冲突检查 | GX Works3 有「分配软元件检查（重复检查）」，覆盖字/位/双字/结构体/数组重叠 | SH081271 `text/08003.html`【已验证】→ 本工具 analyzer 的 `checkAddressCollision`（`analyzer.ts:304-318`）是空实现（两个分支都直接 return） |
| 块注释/`=>`/`//!DECLARE` | `//!DECLARE` 在 GX Works3/FX5 手册中未检索到；文档称“导出至文件→在外围添加声明/注解”生成该格式，但该选项在手册中对应的是**梯形图**导出 | 【代码假设·待验证】 |

### 3.8 标签 CSV（`emit/label-csv.ts`）

## 6. 最可能导致「本地检查通过但 GX Works3 编译失败」的 5 个点

按风险从高到低（每条都含具体触发路径）：

1. **VAR 声明位置/声明块误用（P0）**
   - 现象：`text.ts:132-152 renderPOUDeclarations()` 生成 `//!DECLARE + VAR…END_VAR`；`renderProjectAsText()` 还会拼 `PROGRAM …` 外壳（`text.ts:159-177`）。这些文本一旦被粘进「程序本体」即语法错误；且 `//!DECLARE` 在 GX Works3 手册中无依据。
   - 另一面：标签 CSV/局部标签未先导入时，正文中的变量全部“未定义”。交付流程必须把「标签导入 → 正文粘贴 → 转换」作为强顺序步骤并校验。
   - 建议：交付物只保留 `renderPOUAsText` 的语句部分（可选顶部注释需先验证块注释语法）；删除/隔离声明块输出；编译前检查标签 CSV 是否已导入。

2. **X/Y（及 B/W）进制与 FX3U 口径范围（P0）**
   - 现象：`parseDeviceAddress` 十进制 + `DEVICE_RANGES` FX3U 上限。
   - 编译失败路径：AI 写 `X198`（8/9 非八进制）→ 数值 198≤511 通过本地检查 → GX Works3 输入/编译报错；或 `M1000`/`X1000` 被本地误判越界，AI 被迫改用错地址。
   - 建议：profile 为每个软元件定义 `base: 8|10|16` 与 `[min,max]`（按进制比较），并支持 FX5UJ 等机型差异；iQ-R 复用同一机制。

3. **指令/函数调用形态与参数个数（P0）**
   - 现象：把**指令**（MOV/SMOV/BLKMOV/SET/RST/PLS/PLF/HIOEN/RAMPF）当普通函数或 FB；把 `ADD/MUL/MIN/MAX/MUX/CONCAT` 的参数上限写错（手册 ADD/MUL/MIN/MAX 最多 28 输入，CONCAT 2–28，MUX 3–29）。
   - 编译失败路径：AI 按白名单写 `MOV(a,b)` / `SET(TRUE,bLatch)` / `RAMPF(...)` 返回赋值 → GX 语法/类型错误；或写 3 输入 ADD 被本地误拒后模型“修正”为错误写法。
   - 建议：白名单区分 `instruction（EN/ENO 形态）`、`generalFunction`、`standardFb`、`userFb` 四类，分别校验调用形态；未验证类目一律标 `unverified` 并禁止进入提示词。

4. **FB 名称与形参/调用语法（P0）**
   - 现象：`OUT_M/OUT_H/OUT_L/TIMER_T/COUNTER_FB/RAMP/HIOTRK/DHIO_TRK/MC_*` 均不存在（6 本手册全文检索）；正确名为 `COUNTER_FB_M`、`TIMER_*_FB_M`、`RAMPF`（指令）。
   - 调用语法：手册 FB 示例输出形参用 `:=`（`Q:=d1`），代码/提示词全用 `=>`（未验证）；`tTimer.Q` 成员访问未验证；FB 实例（`t : TON`）需在标签编辑器中建 TON 类型标签，未建则“未定义 FB 实例”。
   - 建议：在 GX Works3 上建立「FB 调用语法验证矩阵」（`=>` vs `:=`、`.Q`、类型标签），把结论写回 profile；提示词只保留已验证的 FB。

5. **类型/字面量/结构语法（P0-P1）**
   - 类型：FX5 **不支持 LINT/ULINT/LREAL**（本地 analyzer 放行 → GX 编译失败）；缺 TIMER/RETENTIVETIMER/COUNTER/LCOUNTER/POINTER（正确写法被本拒）。
   - 字符串：`STRING` 必须单引号、`STRING[Unicode]` 双引号（已验证），但提示词未写规则；AI 用双引号写 STRING → 类型不匹配/编译错误。
   - 结构：REPEAT 缺 `END_REPEAT`（待验证，若 GX 要求 END_REPEAT 则全错）；`(* *)` 块注释（工具自己生成，待验证）；`SQRT` 只能用通用功能（代码正确，但需在提示词中写明“禁止 SQRT 指令/ENO 形态”）。
   - 建议：类型表按 CPU profile 收窄；提示词补字符串/注释/REPEAT/SQRT 规则；所有未验证语法加入 `docs/research/` 验证清单并在原生编译阶段回归。

---

## 7. 结论

1. **v0.1 的定位**：是一个「可演示的 ST 文本生成 + 标签 CSV 导出」原型，不是可交付工具。最有价值的资产是 **标签 CSV 生成器**（与真实导出字节一致）与**解析/输出骨架**；最危险的是「三菱事实库」——设备范围、类型、指令/FB 名称与调用形态大量错误，导致本地检查既误报也漏报。
2. **复用**：`ai/client.ts`、`emit/label-csv.ts`、`emit/text.ts` 主流程、`ai/convert.ts` 外壳拼装、CLI 参数/诊断输出框架、`dialect` 的词法/表达式骨架。
3. **重写**：`dialect/recovery.ts`、`dialect/instructions.ts`+`types.ts`（数据表）、`ai/prompt.ts`（知识部分）、`dialect/analyzer.ts`（规则层）、REPEAT/注释/行号相关解析与反解析。
4. **新增**：`src/profile/`（事实库+来源+验证状态）、spec 层、native 编译/仿真验证层、交付层、入仓 fixtures 与 fuzz/e2e 测试。
5. **下一步（最小可验证闭环）**：选 1 个 FX5U 样例（如 `motor_demo.st`）→ 标签 CSV 导入 + 正文粘贴 → GX Works3「全部转换」成功 → 记录完整证据链，用这条链反向修正 profile 与提示词。
