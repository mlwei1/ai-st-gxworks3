## 下一步最小验证（M2）

1. 生成一个 spec 工程（如 `bench/b_motor_start_stop.json`），导入纯 ST 模板并编译 0 error；
2. `Debug → Simulation → Start Simulation`，确认仿真启动、连接目标切换为仿真；
3. `在线 → 监视 / 监视表` 观察 `X0/Y0` 等软元件随写入变化；
4. 记录：
   - 启动仿真需要的前置条件（工程已编译、连接目标设置、是否需保存）；
   - 仿真窗口标题/进程（`FSimRun3.exe`?）与退出方式；
   - 能否用 UI 自动化稳定地"写 X0 → 读 Y0"，为 test DSL 提供执行器。
5. 若能稳定读写，再设计 M2 的 YAML test DSL 执行器（stimulus → observe → assert）。

## 风险与备选

- GX Simulator3 无公开自动化 API；预计仍需 GX Works3 GUI（MCP UI 自动化）驱动，
  稳定性低于静态检查，需要超时/重试和截图留证；
- 若仿真启动受阻（如缺少虚拟网络/许可），退化为「不启动仿真的在线模拟」或 M2 仅做
  test DSL 的静态/结构校验，并在文档中明确边界。
