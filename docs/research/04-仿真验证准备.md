## 风险与备选

- GX Simulator3 无公开自动化 API；预计仍需 GX Works3 GUI（MCP UI 自动化）驱动，
  稳定性低于静态检查，需要超时/重试和截图留证；
- 若仿真启动受阻（如缺少虚拟网络/许可），退化为「不启动仿真的在线模拟」或 M2 仅做
  test DSL 的静态/结构校验，并在文档中明确边界。

## 验证结果（2026-11-10，GX Works3 1.128 + GX Simulator3）

**最小闭环已打通**：

1. `gen bench/b_motor_start_stop.json` → 导入纯 ST 模板 → 全部转换 **Error 0 / Warning 0**；
2. **Debug → Simulation → Start Simulation** 启动成功（状态栏 `Simulation (1)`，标题进入
   `Monitoring (Read Only)`）；
3. 批监视（`Online → Monitor → Device/Buffer Memory Batch Monitor`）监视 `X0`，写入 `X0=1`；
4. 监视 `Y0` 得到 **1**（启动自锁生效）；证据：
   `docs/evidence/M2/01-simulation-x0-to-y0.png`。

**发现并修复一个真实 bug**：

- 之前 XML 固定输出 `<ResourceExecutionType type="initial"/>`，导入后程序落在 **Initial**
  （初始执行一次），仿真中写 `X0` 后 `Y0` 始终为 0；
- 官方样例中循环程序文件用 `type="scan"`；已将发射器改为 `scan`，重新导入后程序落在
  **Scan**，仿真中写 `X0=1` → `Y0=1` 正常。
- 回归测试：`test/iecxml.test.ts` 断言 XML 含 `<ResourceExecutionType type="scan"/>`。

**操作要点（供 M2 test DSL 执行器参考）**：

- 启动仿真后 GX 会先弹 `Write to PLC` 流程把工程写入仿真器（实测可自动完成）；
- 批监视的“设备名”输入框接受 `X0`/`Y0` 等起始设备（一次显示 16 点），Enter 后需再点
  `Start Monitoring`；
- 位软元件单元格可双击后输入 `1/0` 并回车写入（读模式/写模式都可用，写模式更稳）；
- 读值建议切回设备名后重新 `Start Monitoring`，截图留证；注意自锁回路的停止需写 `X1`。
