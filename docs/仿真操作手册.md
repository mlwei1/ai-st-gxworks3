# GX Works3 / Simulator3 仿真操作手册（人工执行 + 自动化现状）

> 用途：把生成的 ST/XML 导入 GX Works3，在 Simulator3 中运行并记录观测数据。
> 本手册与 `sim/` 场景 DSL、`docs/evidence/M3/` 证据配套使用。

## 0. 先清理残留进程

GX 被强制结束后，残留的 `FSim3Dlg`（GX Simulator3）会让“模拟(n)”实例号持续增长，
导致监视连到旧实例、写入看不到效果。**仿真前先运行**：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/reset-sim.ps1
```

期望输出：`清理完成：GXW3=0, FSim3Dlg=0`。

## 1. 新建工程

1. 打开 GX Works3（FX5U）；
2. 工程 → 新建：系列 **FX5U**、机型按实物、**程序语言选「不指定」**；
3. 不要生成 SFC 骨架程序（空 SFC 会报 Action0/Transition0 未定义）。

## 2. 导入 IEC 61131-10 XML

1. 工程 → 导入文件 → IEC61131-10 XML格式；
2. 选 `out/xxx/xxx.xml` → 打开；
3. 弹窗「读取指定文件的内容。确定吗？」→ **是(Y)**；
4. 转换 → 全部转换 → 执行；等结果弹窗出现，确认 **Error:0**；
   - 若有 Error，先修程序/XML，不要继续（写入会静默失败并显示旧程序数据）。

## 3. 启动仿真（自动写入）

调试(B) → 模拟(S) → 模拟开始(S)：

- 会弹出「写入至可编程控制器」进度窗口，**等它自己消失**（10~40s，视工程大小）；
- 不要此时打开批量监视（会拿到旧快照）；
- 仿真窗口 `GX Simulator3` 应显示：PWR 绿灯、RUN 选中、**P.RUN 绿灯**。

## 4. 自查：程序是否真的在执行

打开 在线 → 监视 → 软元件/缓冲存储器批量监视，输入 `SM400`：

- SM400 = 1 → CPU 在 RUN；
- 再用一个“每扫描自增”的探针寄存器（如 `sim/probe_scan.st` 的 D0）确认程序在扫描；
- 如果 SM400=1 但目标寄存器恒 0 → 程序多半没写进去（回第 3 步看写入进度窗口）或监视连到旧实例（回第 0 步）。

## 5. 读取观测值

1. 软元件名 输入 `D300` → 回车 → 点「监视开始(S)」；
2. 温度 harness 期望（`sim/temperature_two_position.harness.st`）：

| 设备 | 期望 | 含义 |
|---|---|---|
| D310 | 0 | 阶段0：未启动，Y0/Y1=0 |
| D311 | 1 | 阶段1：冷态启动，加热 ON |
| D312 | 0 | 阶段2：到设定 600，加热 OFF |
| D313 | 2 | 阶段3：620（设定+回差），冷却 ON |
| D314 | 0 | 阶段4：回 600，冷却 OFF |
| D315 | 0 | 阶段5：2000 超量程，故障停输出 |
| D316 | 1 | 阶段6：回 0 重启，加热 ON |
| D320 | **0** | 自检 PASS（1=FAIL） |

3. 截图存 `docs/evidence/M3/`，并把观测值写入 `sim/temperature_two_position.obs.json`
   （格式：`{"D310":0,"D311":1,...}`），运行：
   `node --experimental-strip-types --no-warnings src/cli.ts sim sim/temperature_two_position.sim.json --observed sim/temperature_two_position.obs.json`

## 6. 已知环境坑（实测）

| 现象 | 原因/处理 |
|---|---|
| 监视全 0，但 SM400=1 | 监视窗口在写入前打开 → 关闭监视，等写入完成再开；或 GX 残留实例 → 先跑 `tools/reset-sim.ps1` |
| `模拟(n)` 的 n 一直增大 | 残留 `FSim3Dlg` 进程 → `tools/reset-sim.ps1` |
| 转换 Error>0 | 写入会被拒绝并弹「存在以下写入对象文件，因此无法写入」→ 先修 Error |
| RS2 报 `0x12011070` | `n1/n2/n3` 不能是未分配软元件的标签，必须写常数/软元件（见串口模板文档） |
| SM412 计数快速回绕 | Simulator3 中 SM412 可能恒 ON，不要用其上升沿做分频；改用 TON 节拍 |


## 8. 2026-11-11 深度排查记录（程序写入后仍不执行）

按本手册完整执行后仍出现「写入显示已完成、CPU RUN/P.RUN 绿灯，但 D0=0、D310~D316=0」：

1. `在线 → 写入至可编程控制器 → 执行(E)`；
   - 注意：**「执行(E)」可能置灰**（未展开/未勾选写入对象时），需先选「参数+程序(F)」；
2. 确认「远程STOP后写入」→ 是；覆盖确认 → 全部是；「是否执行远程RUN」→ 是；
3. 提示「已完成」，仿真窗口 P.RUN 绿灯；
4. 但批量监视 D0（harness 每扫描自增）仍为 0，说明 **PLC 里实际没有执行本工程程序**；
5. `在线 → 与可编程控制器校验(V)` 报「校验对象文件不存在，或对象中包含不同的文件名」——
   源工程名是「工程未设置」，目标 PLC 名是「FX5U」，**名称不一致**，无法比对，
   因此该报错不能证明“程序不存在”，但也无法确认写入内容。

下一步排查方向（优先级）：
- **先把工程另存为命名工程**（工程 → 另存为，例如 `FX5U.gx3`），再启动仿真/写入；
  未命名工程（工程未设置）可能是写入/校验异常的原因；
- 写入后先做一次「读取程序」回读，确认 PLC 内 Main 内容；
- 确保仿真只有 1 个实例（先跑 `tools/reset-sim.ps1`），避免监视连到旧实例；
- 若仍不行，退化为**人工在 GX 中导入→写入→监视**，按本手册记录数据。
## 7. 自动化边界

当前 MCP/UI 自动化可以完成：建工程、导入、转换、启动仿真、打开监视、读数、截图；
但**外设（X/D）写入、远程 STOP/RUN 确认、覆盖确认**这类对话框交互尚不稳定，
因此完整仿真闭环目前按本手册**人工执行**；自动化只做“读数 + 证据截图”。
