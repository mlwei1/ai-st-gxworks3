# 怎么提需求、怎么生成 ST 程序给你检查

## 方式 A：直接跟我说（推荐）

用中文把控制要求说清楚就行，例如：

> "冷却风扇：按下启动 X0 后风扇 Y0 运行，满 10 秒自动停；按停止 X1 立即停；
> 故障 X2 停机，故障消失后要重新按启动。"

我会做三件事：
1. 把它整理成 `specs/<名字>.json`（IO 表 + 需求编号 R1/R2…）；
2. 跑 `gen` 生成 `<名字>.st`（纯 ST）+ IEC XML + 标签 CSV；
3. 跑 `check` 校验，然后把 **ST 源码**和文件路径发你检查。

## 方式 B：你自己写 spec（确定性，适合批量）

复制 `specs/motor_start_stop.json` 改字段即可，核心字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `name` / `title` | 工程名 / 中文标题 | `demo_fan_auto_stop` |
| `cpu.series/model` | CPU 系列与型号 | `FX5U` / `FX5U-32MT/ES` |
| `template.name` | 用哪个模板（见下表） | `motor_auto_stop` |
| `template.params` | 模板参数 | `{ "autoStopSec": 10 }` |
| `io[]` | 设备分配：`device`/`name`/`type`/`comment` | `X0` / `bStart` / `BOOL` |
| `requirements[]` | 需求条目（编号 + 文字），会写进生成文件头 | `R1 按下启动后运行` |
| `safety.interlocks[]` | 安全/联锁要求 | `bFault 为 ON 时禁止输出` |

然后执行：

```bash
# 一条命令：ST + IEC XML + 标签 CSV + manifest
node --experimental-strip-types --no-warnings src/cli.ts gen specs\demo_fan_auto_stop.json -o out\demo_fan

# 校验 ST（语法 + 三菱方言）
node --experimental-strip-types --no-warnings src/cli.ts check out\demo_fan\demo_fan_auto_stop.st
```

输出目录里各文件是什么：

| 文件 | 用途 |
|---|---|
| `<name>.st` | **给你检查的纯 ST 源码**（可直接读、可复制进 GX Works3） |
| `<name>.xml` | IEC 61131-10 工程包，GX Works3 可导入（推荐方式） |
| `Main_local_labels.csv` / `Global.csv` | 标签表（备选导入通道用） |
| `manifest.json` | 生成记录（spec、模板、诊断），便于追溯 |
| `diagnostics.json` | 结构/代码诊断，全空表示没问题 |

## 模板库（8 个，先看有没有匹配的）

| 模板 | 适用场景 | 关键参数 |
|---|---|---|
| `motor_start_stop` | 电机启停 + 自锁 + 故障联锁 | `faultReset` |
| `motor_auto_stop` | 启动后定时自动停止 | `autoStopSec` |
| `motor_reverse_interlock` | 正反转互锁 + 换向死区 | `deadTimeSec` |
| `timer_sequence` | N 步定时时序（每步延时） | `stepCount`、`stepNSec` |
| `counter_batch` | 计数到批量值输出，复位清零 | `batchSize` |
| `state_machine` | 待机/运行/停止状态机（含兜底） | 无 |
| `analog_scale` | 模拟量线性标定 + 限幅 | `rawMin/rawMax/engMin/engMax` |
| `alarm_first_out` | 报警锁存 + 首出 + 确认 + 复位 | `alarmCount` |

不在模板库里的需求：可以走 LLM 通道（`generate "<需求>"` 或 `gen --llm`），
但当前机器的 LLM 凭据未配置（调用会报 `LLM_E_CALL: 未配置 LLM 凭据`）；
也可以先告诉我，我按模板风格手写 ST，再跑 `check` 校验。

## 生成后怎么检查（3 点）

1. **看头部**：需求编号 R1/R2… 与参数是否和你提的一致；
2. **看变量**：`VAR ... END_VAR` 里的变量名、类型、初值；
3. **看逻辑**：按需求逐条对照（如"故障时立即停"要有 `IF bFault ... := FALSE`）。

更严格的话可以配套写仿真场景（`sim`），在 GX Simulator3 里逐条验证，
参考 [M2 验收复核指南](M2-验收复核指南.md)。

## 本次演示

需求："冷却风扇启动 X0 后运行 10 秒自动停，停止 X1 立即停，故障 X2 停机"。

生成结果：`out/demo_fan/demo_fan_auto_stop.st`（`check` 校验通过，0 error）。

```st
PROGRAM Main
VAR
    bRun : BOOL := FALSE;
    bFault : BOOL := FALSE;
    tAutoStop : TON;
END_VAR
    IF X2 THEN
        bFault := TRUE;
    END_IF;
    IF bFault OR X1 THEN
        bRun := FALSE;
    END_IF;
    IF X0 AND NOT X1 AND NOT bFault THEN
        bRun := TRUE;
    END_IF;
    tAutoStop(IN := bRun, PT := T#10000ms);
    IF bRun AND tAutoStop.Q THEN
        bRun := FALSE;
    END_IF;
    Y0 := bRun;
END_PROGRAM
```
