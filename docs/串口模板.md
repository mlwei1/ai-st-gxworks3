# 串口模板（serial_send_recv）

> 第四个工业场景模板：**FX5U 串口无协议收发**（RS2 指令的 ST 形态）。
> 指令 ST 形式已通过 GX Works3 原生编译验证（Error:0）。

## 1. 用法

```bash
node --experimental-strip-types --no-warnings src/cli.ts gen specs/serial_send_recv.json -o out/serial_send_recv
```

示例 spec：[specs/serial_send_recv.json](../specs/serial_send_recv.json)

```json
"template": {
  "name": "serial_send_recv",
  "params": { "channel": 1, "sendBytes": 8, "recvBytes": 8, "timeoutMs": 3000 }
}
```

| 参数 | 含义 | 默认 / 范围 |
|---|---|---|
| `channel` | 通信通道 | 1（1..4，需与模块参数一致） |
| `sendBytes` | 发送字节数 | 8（1..1024） |
| `recvBytes` | 接收字节数 | 8（1..1024） |
| `timeoutMs` | 通信超时 | 3000（100..10000ms） |

IO 约定（`spec.io` 顺序）：

| 角色 | 默认设备 | 说明 |
|---|---|---|
| 启动 | X0 | 上升沿触发一次收发 |
| 复位 | X1 | 清除完成/异常 |
| 通信中 | Y0 | 请求进行中 |
| 正常结束 | Y1 | 收发成功 |
| 异常结束 | Y2 | 超时/异常 |
| 发送区 | 第一个 D（D100） | 待发送数据（sendBytes 字节） |
| 接收区 | 第二个 D（D200） | 接收数据（recvBytes 字节） |

## 2. 生成逻辑（节选）

```st
// RS2：ENO := RS2(EN, s, n1, n2, n3, d)
//   n1/n2/n3 必须是软元件或常数，不能是未分配软元件的标签 → 直接写常数
IF bReq THEN
    bEno := RS2(TRUE, D100, 8, 8, 1, D104);

    // 发送待机标志 ON → 发送中
    IF SM8401 THEN
        bSending := TRUE;
    END_IF;

    // 完成：发送待机 OFF 且接收点数 > 0
    IF bSending AND NOT SM8401 AND SD8403 > 0 THEN
        bReq := FALSE;
        bDone := TRUE;
    END_IF;

    // 串口超时判定 / 软件超时
    IF SM8409 THEN
        bReq := FALSE;
        bErr := TRUE;
    END_IF;
    tTimeout(IN := bReq, PT := T#3000ms);
    IF tTimeout.Q THEN
        bReq := FALSE;
        bErr := TRUE;
    END_IF;
END_IF;
```

特殊软元件（FX5 应用篇 p789/p790/p827，通道 n 偏移 20）：

| 通道 | 发送待机 SM | 超时判定 SM | 接收点数 SD |
|---|---|---|---|
| CH1 | SM8401 | SM8409 | SD8403 |
| CH2 | SM8421 | SM8429 | SD8423 |
| CH3 | SM8441 | SM8449 | SD8443 |
| CH4 | SM8461 | SM8469 | SD8463 |

## 4. 使用前提与坑

1. **模块参数**：GX Works3 中配置串口通信格式（波特率/数据位/校验/停止位/超时），
   通道与模板参数一致；
2. **RS2 操作数限制**：`n1/n2/n3` 只能指定软元件或常数；
   传“未分配软元件的标签”会报错 `0x12011070 指令中指定了不可使用的标签`（已实测并修正）；
3. **发送区/接收区**：不能与程序中其他数据重叠；
4. **触发方式**：本模板是一次触发；循环轮询由用户按节拍触发 X0；
5. **超时**：串口超时判定（SM 标志）与软件超时（TON）双保险；
6. **安全**：串口通信不得作为唯一安全联锁。
